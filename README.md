# 项目交付协作平台

围绕需求、任务、成员分工和成果确认，帮助小团队完成一次项目交付。AI 辅助整理任务草案和接手说明。

手动交付流程已接通。成员可从创建任务推进到成果提交、退回重提、撤回或确认通过，并查询历次成果。项目支持职责恢复、文档版本历史，以及从成果材料回查提交时选定的版本。Flyway 管理业务表、会话、命令回执、活动和待投递提醒。Python／FastAPI 服务安排在 P4。

## 本地运行

使用 JDK 21、Node.js 22.18+（22.x）或 24.12+，以及可连接的 MySQL 8.4。当前 WSL 环境使用本机 MySQL，开发库为 `project_for_job`。服务未运行时执行 `sudo service mysql start`。将应用账号的连接地址、用户名和密码配置在仓库外的 `~/.config/project_for_job/mysql.env`。

在仓库根目录打开两个终端。第一个启动后端，应用会执行 Flyway 迁移。首次创建本地演示账号时，启用 `demo` profile 并输入自选密码（12–72 个 UTF-8 字节）。数据库连接密码仍由 `mysql.env` 提供。

```bash
source "$HOME/.config/project_for_job/mysql.env"
cd business-api
read -rsp '设置 demo 的登录密码: ' demo_password
printf '\n'
PROJECT_DEMO_PASSWORD="$demo_password" ../scripts/direct ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
unset demo_password
```

账号创建后，后续启动可以直接运行下面的命令。

```bash
../scripts/direct ./mvnw spring-boot:run
```

第二个启动前端。

```bash
cd web
../scripts/direct npm ci --no-audit --no-fund
../scripts/direct npm run dev
```

打开 `http://127.0.0.1:5173`，使用 `demo` 和刚设置的密码登录。刷新页面后会使用 Cookie 恢复当前用户，退出会使服务端会话失效。Vite 将 `/api` 转发至本机 `127.0.0.1:8080`。健康检查可以访问 `http://127.0.0.1:8080/actuator/health`。

### 体验空间、项目与成员

1. 登录后创建空间，再在空间里创建“团队邀请”项目。创建者自动是空间管理员和项目负责人。
2. 想体验两个账号时，首次创建第二个演示账号，可在启动后端的那条 `demo` 命令前同时设置 `PROJECT_DEMO_LOGIN=demo-observer` 和新选的 `PROJECT_DEMO_PASSWORD`。同名账号会保留已有密码。
3. 管理员先按登录名将第二个账号添加到空间，再从空间成员中选择对方并加入项目。只有加入空间时，对方可以看到空间。加入项目后，对方才可读取该项目的资料和成员。

### 体验任务从待梳理到进行中

1. 在项目页新建待梳理任务。可以先提交标题，再打开任务补齐目标、预期成果和至少一项完成条件。
2. 负责人或有执行权限的任务创建者点击“整理就绪”，任务进入待开始。若记录了疑问，先在页面确认影响范围或验收的疑问均已解决。
3. 负责人从有效项目成员中指定执行者和确认人。两个职责可暂留空，分派给同一个人时接口会拒绝。旧版本保存遇到冲突时，页面保留待提交内容，可显式载入最新版本。
4. 执行者空缺时，有执行资格且未被指定为本任务确认人的项目成员可以点击“领取任务”。领取后任务保持待开始。当前执行者点击“开始执行”后，任务转为进行中，列表可以按新状态筛选。

### 体验成果提交与确认

1. 准备两个有效项目成员，分别担任执行者和确认人。确认人可以在任务开始后由负责人补派。
2. 执行者在进行中的任务里填写成果说明，添加至少一项正文、链接或固定文档版本，提交后进入待确认。执行者或负责人可以填写原因并撤回本轮。
3. 确认人查看本轮材料后可以通过或填写意见退回。执行者修改后再次提交会生成新一轮。每轮的材料、提交时的确认人和实际决定都可在成果历史中查询。
4. 按原请求键重试可查回原动作。遇到轮次或版本冲突时，先刷新任务和成果再核对。提醒目前保存为待投递记录，站内投递在 P3 接入。

### 体验成员撤权和职责恢复

1. 在项目成员列表打开“管理成员”，查看他的未完成执行、确认职责，再直接打开关联任务。普通移除要求先移交这些职责。
2. 选择“立即撤权”并填写原因后，原账号保留登录，但失去该项目的读取、操作和回执访问资格。空间撤权同时失效该空间下的项目资格。两种操作都会保护最后一名有效负责人，空间还须保留一名有效管理员。
3. 若待确认任务的确认人失效，负责人可更换确认人。若执行者失效，先管理撤回本轮成果，再指派接任者，由接任者重新提交。任务和成果历史仍可查。
4. 需要重新加入时，先恢复空间资格，再由项目负责人显式恢复项目资格。空间级操作被项目职责阻止时，响应中的项目 ID 可用于联系相应负责人。

### 体验固定版本文档

1. 在“项目文档”新建 Markdown 文档。打开版本历史可查看当时的标题、正文、编辑者和变更说明。页面以原文展示 Markdown。
2. 用同一账号打开两个窗口，分别编辑同一版本。在第一个窗口保存后，第二个窗口保存会收到冲突。第二个窗口会保留稿件，可与最新正文对照，手工合并后明确采用最新版本作为保存基准。
3. 提交成果时选择“固定文档版本”，选中具体文档和版本。更新项目文档后，在成果历史里点开该材料，核对版本号和当时的正文。

后端用 `../scripts/direct ./mvnw verify` 构建和测试，需要先加载数据库环境变量。登录、项目权限和任务接口测试使用临时账号、会话与业务数据，结束后会清理。前端用 `../scripts/direct npm run build` 检查类型并构建。

## 软件包下载

从仓库根目录用 `scripts/direct <命令>` 下载软件包或依赖，在模块目录中使用 `../scripts/direct`。它清除进程的代理变量，对 npm 禁用代理配置，对 Maven 使用仓库内的空代理设置。以后安装 Python 依赖时，也用 `../scripts/direct pip install -r requirements.txt` 或 `../scripts/direct python -m pip install -r requirements.txt`。pip 通过该入口读取不到用户的代理配置。直连失败按源地址排查。
